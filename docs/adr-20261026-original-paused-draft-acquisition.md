# Original paused-draft preservation

Date: 2026-10-26
Status: Source contract

The original production package can bind exactly two desktop drafts for preservation. Their identities, preparation request, exact capture reference and storage binding belong to the existing retained-disposition hash. Original rows and source objects remain untouched. New-ID recovery remains separate.

A dedicated read-only preparation workflow reads its strict request from an immutable private operations commit. It verifies the hosted source/run/job and native AWS caller before querying either draft. Strongly consistent queries project structural parent fields and indexed source bindings, excluding titles, labels, filenames and errors. HEAD requests are limited to approved source keys. Version discovery is immediately followed by an exact-version HEAD.

The pure preparation-role proposal renderer derives its trust, permission profile and native matcher inputs from the same strict request. It grants source reads only for listed keys and versions, personal queries only for the two partitions, and capture writes only in the operation's evidence namespace. Missing source encryption or a required KMS key remains an unresolved proposal input. An optional approved encryption predicate is compared with actual HEAD metadata. Rendering a proposal neither checks nor installs permissions.

The producer stores the structural capture through the existing private capture store, which checks its configured versioning, encryption, privacy and lifecycle. Its Actions artifact contains sanitized request/capture commitments and preparation provenance. The original package loader authenticates the terminal successful run, actual artifact archive digest, private request and exact-version capture bytes. It accepts introduction and native collector bindings separately, retaining opaque token references privately.

The existing no-argument launcher-settings producer verifies actual role identities, trust and complete policy snapshots. Its private receipt also checks the fixed preservation grants for the exact draft partitions and object versions. Both that receipt and the cohort token are checked before and after every native metadata read. IAM GetObjectVersion can grant content access; HEAD-only behavior is enforced by the native reader.

Acquisition reconciles the two drafts with the complete retained inventory, including reverse personal-history links. The original process-exclusion and unrelated uncertain-effect refusals remain. After exclusion, the existing initialization transaction checks structural metadata and installs both pause markers atomically with Control and its initialization receipt. It never writes the original parent or segment items. Later preservation requires the original journal's durable direct acknowledgment, reconstructed initialize request and paired marker readback. Marker presence alone cannot settle a lost acknowledgment.

Final collection rechecks exact versions, table TTL and bucket lifecycle settings. Final transactions merge structural draft conditions with the complete retained guards and both marker snapshots. Indexed source conditions include list type, cardinality and every supported source field. Complete typed runtime and fixture-authority envelopes replace only their previous conservative size placeholders; partially projected items retain the 400 KiB ceiling.

Available checksums retain their field names and approved predicate sources. Unknown names and conflicting predicates refuse. Provider-reported full-object checksum evidence is distinct from independently downloading and hashing bytes. Missing optional checksum evidence remains UNKNOWN.

Capture authentication proves provenance and integrity. It does not establish absent historical effects, omitted text values, administrator exclusion or permanent retention. Historical effects remain UNKNOWN. Actual operational exclusion of unsupported writers and policy mutation, production permission/storage provisioning and execution remain separate prerequisites. This source change does not authorize live draft reads, marker installation, IAM changes or deployment.
