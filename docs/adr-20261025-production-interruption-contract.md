# ADR-20261025: Keep interruption acceptance separate from staged introduction

Status: Accepted for source preparation; production execution blocked.

## Decision

Prepare A as an attended legacy interruption followed by isolated fixture acceptance, ordinary-admission reopening and a separate deployment release. Preserve the upstream staged protocol under separate module names and strict schemas. Its unavailable-authority refusal remains in place.

The [production interruption contract](production-interruption-contract.md) defines admission, retained ownership, direct acknowledgment, finite capacity, private Terraform and launcher evidence. The [earlier staged ADR](adr-20261020-production-legacy-introduction.md) continues to describe its separate protocol.

## Consequences

Neither workflow may translate the other's receipts into authority. The original A package must account for the actual staged route, its session limits and foreign active or resumable runs. Current static credential acquisition in deployment and conditional Sandbox Apply makes the checked-out source unsupported for A activation. Synthetic OIDC-only tests do not establish production compatibility.

The existing prompt-guard role gains the exact OpenAI-secret read and the platform-supported metadata permissions needed by the existing connection-sync job. Every trusted consumer of that role gains the same exposure. Actual provisioning and credential retirement require separate execution review.

The privileged recovery-publication CLI remains an operational exclusion with an independent freeze requirement. Its readback-confirmed terminal state cannot settle an unknown acknowledgment for A. No global writer-fencing claim is made.

## Alternatives

Taking either colliding implementation wholesale would discard reviewed behavior. Combining their manifests or accepting caller-provided receipts would blur authority. Migrating every static credential route or adding an admitted recovery-publication executor would require separate scope and review. These changes are deferred.

## Paused personal drafts

Preserve the public paused-draft protocol separately from A acceptance. Its marker and staged capture token cannot make incomplete personal work safe terminal. Reuse A's existing personal classification in the initial metadata scan to refuse known infeasible inventory before interruption, while keeping post-stop and final checks. This can refuse an attended window that needs a separately reviewed preservation contract; it avoids deliberately entering maintenance with personal work already known to block reopening. The screen is non-atomic and cannot guarantee later eligibility.
