# Ask agent with S3 Vectors implementation plan

> For agentic workers: use superpowers:executing-plans or superpowers:subagent-driven-development task by task. This is an investigation and implementation draft, not an instruction to deploy or provision paid services.

**Goal:** Give every tier an Ask agent that finds meetings through their complete notes and investigates transcripts only within selected meetings.

**Architecture:** Pi runs in the existing API process with user-bound shared meeting tools. DynamoDB/S3 remain authoritative. Qualify two S3 Vectors ENHANCED indexes for meeting records and transcript passages; no additional PostgreSQL database.

**Tech stack:** Existing Node 24, TypeScript, React, tRPC, DynamoDB, S3 and Langfuse; a pinned compatible Pi package and official AWS client-s3vectors; existing OpenAI embeddings API. Proposed change projection uses DynamoDB Streams, one Lambda, failure destination and reconciliation.

**Spec:** [Ask agent with S3 Vectors](../specs/2026-11-17-ask-agent-design.md).
**Tool contracts:** [Arguments, results and source rules](../specs/2026-11-17-ask-agent-tools.md).

## Global constraints

- Identity and scope come from backend authentication. Current meeting/artifact access and source revision win over indexed metadata.
- No public-MCP OAuth loopback, Hub credentials, arbitrary execution tools, subagents or autonomous writes.
- No recent-N tier entitlement. Provider query limits are not restrictions on eligible history.
- One complete meeting record with full notes. Search that first; transcript search requires nonempty previously loaded meeting references. No global transcript query, title/summary boosts or cross-index merging.
- Preserve model parameters, mention handling, citations, privacy rules and existing release approvals.
- Keep model/dimensions/source/input-hash provenance. No mixed embedding generations or hidden partial coverage.
- Index/embedding failures never block meeting delivery. Uncertain writes and stale source revisions cannot become trusted evidence.

## Review focus

1. Provider text/vector requirements quietly breaking complete-note or lexical-only guarantees.
2. Transcript-only matching leaking through title/rank/count or bypassing the meeting-first rule.
3. Backfill/late writes restoring deleted or superseded evidence.
4. Provider topK/filter limits represented as full result exhaustion.
5. Uncertain send/restart/another replica duplicating work or defeating Stop.

Tasks below own these checks.
